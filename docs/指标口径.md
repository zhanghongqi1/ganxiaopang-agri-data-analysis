# 「甘小胖」经营分析指标口径（流量-转化-复购-履约四层体系）

> 适用范围：ganxiaopang_db（模拟数据）。本文档为全项目唯一指标口径来源；
> 同一口径以 SQL 视图形式固化在 `sql/01_metric_views.sql`，报表与看板均从视图/同口径 SQL 取数。
> 统计时间窗：2024-01-01 ~ 2025-12-31；用户行为观察截止日（RFM 快照日）：2025-12-31。

## L1 流量层（直播获客效率）

| 指标 | 口径定义 | 取数来源 |
|---|---|---|
| 曝光量 | 直播场次被推荐流曝光的次数（场次累计值） | fact_live_sessions.total_exposure |
| 进入率 | 进入直播间人次 ÷ 曝光量 | fact_live_sessions |
| 场均观看 UV | 平均每场进入直播间的去重观众数 | fact_live_sessions.total_enter ÷ 场次数 |
| 平均在线人数 | 场次内分钟级在线人数的算术平均 | fact_live_minute_traffic.viewers_online |
| 峰值在线人数 | 场次内分钟级在线人数最大值 | fact_live_minute_traffic.viewers_online |
| 涨粉数 | 场次内新增关注数 | fact_live_sessions.new_followers |
| GPM（千次观看成交额） | GMV ÷ 曝光量 × 1000 | fact_live_sessions |
| UV 价值 | GMV ÷ 进入人数 | fact_live_sessions |

## L2 转化层（成交效率）

六段漏斗（场次级，逐级递减）：

```
曝光 → 进入 → 停留(>30s) → 互动(评论/点赞) → 下单 → 付款
```

| 指标 | 口径定义 |
|---|---|
| 进入率 | 进入人次 ÷ 曝光量 |
| 停留率 | 停留超 30 秒人次 ÷ 进入人次 |
| 互动率 | 互动人次（评论或点赞）÷ 停留人次 |
| 下单率 | 下单人数 ÷ 互动人数 |
| 付款率 | 付款人数 ÷ 下单人数（模拟含 8%-12% 的下单未付款流失） |
| 整体转化率 | 付款人数 ÷ 曝光量 |
| 客单价 | 已付款订单支付金额合计 ÷ 已付款订单数（口径：fact_orders 中 order_status ∈ {已付款, 已发货, 已完成}） |
| 连带率 | 订单明细件数合计 ÷ 订单数 |
| GMV | 已付款订单的 pay_amount 合计（不含已取消/已退款订单） |

## L3 复购层（用户价值，RFM）

观察截止日 T = 2025-12-31。样本：时间窗内有 ≥1 笔已付款订单的用户。

| 维度 | 定义 | 打分方向 |
|---|---|---|
| R（Recency） | 最近一次付款日期距 T 的天数 | 越小越好 |
| F（Frequency） | 时间窗内已付款订单数 | 越大越好 |
| M（Monetary） | 时间窗内累计支付金额 | 越大越好 |

分层方法：R、M 分别按样本中位数二分（R ≤ 中位天数 = 1；M ≥ 中位数 = 1）；
**F 采用「是否复购」二分**（F ≥ 2 = 1）——因真实电商数据中 F 高度右偏（约 78% 用户仅购买 1 次），
若对 F 取中位数会使该维度失去区分度。组合成 8 类人群（实际数据中可辨识 4-6 层）：

| R | F | M | 人群标签 | 运营含义 |
|---|---|---|---|---|
| 1 | 1 | 1 | 重要价值客户 | 近期活跃 + 高频 + 高额，核心资产，VIP 维护 |
| 0 | 1 | 1 | 重要保持客户 | 高频高额但近期沉默，需唤回 |
| 1 | 0 | 1 | 重要发展客户 | 近期购买 + 高客单但频次低，促复购 |
| 1 | 1 | 0 | 重要挽留客户 | 近期活跃频次高但金额低，提客单 |
| 0 | 0 | 1 | 一般价值客户 | 高额一次性，防流失 |
| 1 | 0 | 0 | 一般发展客户 | 新客/低频低额，首购激励 |
| 0 | 1 | 0 | 一般保持客户 | 老客低消费，活动触达 |
| 0 | 0 | 0 | 一般挽留客户 | 低价值，低成本触达 |

| 指标 | 口径定义 |
|---|---|
| 复购率 | 时间窗内付款订单 ≥2 的用户数 ÷ 有付款行为的用户数 |
| 平均复购周期 | 同一用户相邻两笔付款订单间隔天数的均值（仅统计间隔 ≤180 天的相邻订单） |

## L4 履约层（供应链效率与门店经营）

| 指标 | 口径定义 | 取数来源 |
|---|---|---|
| 采购到货周期 | arrival_date − purchase_date（天，按供应商/品类聚合均值） | fact_purchases |
| 库存周转天数 | 平均库存量 ÷ 日均出库量（按主力 SKU 周度快照计算） | fact_warehouse_stock |
| 履约时效 | 签收日期 − 发货日期（天；电商订单配送） | fact_deliveries.lead_time_days |
| 采购损耗率 | 采购验收不合格量 ÷ 采购量 | fact_purchase_items.quality_grade |
| 配送损耗率 | 配送 loss_kg ÷ weight_kg（按模式：旧模式 vs 集中仓储+分级配送） | fact_deliveries |
| 综合损耗率 | (采购不合格 + 配送损耗) ÷ 总投入量 | 上述两项汇总 |
| 门店客单价 | 日销售额 ÷ 日订单数 | fact_store_sales_daily |
| 门店坪效 | 月销售额 ÷ 营业面积（元/㎡/月） | fact_store_sales_daily + dim_stores |
| 门店人效 | 月销售额 ÷ 员工数 | 同上 |
| 单店月净利 | 月毛利 −（房租 + 人工 + 水电杂费 + 平台与营销费用 + 损耗成本） | e_store_pnl 模型参数 |
| 盈亏平衡日均单量 | 固定成本 ÷ (客单价 × 毛利率 − 单均变动成本) | e_store_pnl 模型推导 |

## 渠道与品类口径

| 口径 | 定义 |
|---|---|
| 电商 GMV | fact_orders 已付款订单 pay_amount 合计 |
| B2B 供货额 | fact_b2b_orders.amount 合计（火锅餐饮/商超/特产店等批发供货） |
| 门店销售额 | fact_store_sales_daily.sales_amount 合计 |
| 全渠道 GMV | 上述三项之和；渠道占比以全渠道 GMV 为分母 |
| 品类 GMV | 电商（order_items×订单状态过滤）+ B2B + 门店（门店按品类映射）三来源归集到 category_l1/l2 |
| 品类毛利 | 各渠道销售额 × 对应毛利率（电商/B2B 用 SKU 毛利率，门店用门店品类毛利率参数） |
| 品类 ROI | 品类毛利 ÷ 品类投入成本（内容场次数×场次成本 + 采购成本等归集，详见 sql/a_category_roi.sql 注释） |
| Top3 品类贡献 | GMV 前 3 大品类 GMV 之和 ÷ 全渠道 GMV（校准目标 ≈65%） |
